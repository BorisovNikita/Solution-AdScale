# Стратегии масштабирования баз данных

## 1. Репликация Master-Slave

| Сервис | Стратегия | Обоснование |
|--------|-----------|-------------|
| **Сервис ставок** | Master-Slave репликация | Основная нагрузка - чтение (кампании, ставки, модификаторы). Read replicas используются для offloading аналитики и отчётов. Master для записи (AuctionLog). |
| **Сервис кампаний** | Master-Slave репликация | Высокое соотношение чтения к записи (CRUD редко, чтение часто). Реплики для балансировки запросов от Сервиса ставок. |
| **Финансовый сервис** | Master-Slave репликация | Реплики для отчётов и аудита, master для транзакций. |
| **Сервис статистики** | Не требуется (ClickHouse) | ClickHouse поддерживает репликацию на уровне таблиц (ReplicatedMergeTree). |
| **Сервис аналитики** | Не требуется (ClickHouse) | Использует ту же модель репликации, что и статистика. |

## 2. Шардирование (Sharding)

| Сервис | Ключ шардирования | Обоснование |
|--------|-------------------|-------------|
| **Сервис ставок** | `campaign_id` или `advertiser_id` | Данные о кампаниях и ставках можно шардировать по рекламодателю для равномерного распределения нагрузки. |
| **Финансовый сервис** | `advertiser_id` | Финансовые данные привязаны к рекламодателю - шардирование по этому ключу позволяет изолировать нагрузку. |
| **Сервис статистики** | `date` (партиционирование) | ClickHouse поддерживает партиционирование по дате, что ускоряет запросы по временным диапазонам и упрощает очистку старых данных. |

**Метод шардирования:** Consistent Hashing или диапазонное шардирование по `advertiser_id`.

## 3. Read Replicas

- **Для Сервиса аналитики:** Выделяется отдельная read-replica ClickHouse (или используется репликация на уровне таблиц) для изоляции тяжёлых аналитических запросов от потока записи событий.
- **Для Сервиса ставок:** Read replicas PostgreSQL для балансировки чтения данных кампаний и ставок (кэш используется как основной источник, но при промахах - запрос к реплике).
- **Для Рекламного кабинета:** Используются read replicas PostgreSQL для отображения списков кампаний и отчётов.

## 4. CQRS (Command Query Responsibility Segregation)

Применяется для Сервиса статистики и аналитики:

- **Command side (запись):** Сервис статистики получает события из Kafka и записывает их в ClickHouse (асинхронно, высокая пропускная способность).
- **Query side (чтение):** Сервис аналитики выполняет сложные запросы к ClickHouse для построения отчётов. Используются материализованные представления и агрегации для ускорения запросов.

Для финансового сервиса CQRS не применяется - требуется строгая консистентность, поэтому используются транзакции.

## Резюме

| Компонент | Master-Slave | Шардирование | Read Replicas | CQRS |
|-----------|--------------|--------------|---------------|------|
| Сервис ставок | Да | Да (campaign_id) | Да | Нет |
| Сервис кампаний | Да | Да (advertiser_id) | Да | Нет |
| Сервис статистики | Нет (ClickHouse) | Партиционирование по дате | Нет | Да |
| Сервис аналитики | Нет (ClickHouse) | Партиционирование по дате | Да (отдельная реплика) | Да |
| Финансовый сервис | Да | Да (advertiser_id) | Да | Нет |
