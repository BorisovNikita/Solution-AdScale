# AS-IS анализ текущей архитектуры AdScale

## Общее описание
AdScale - гибридный монолит на нескольких языках, развёрнутый в одном production-кластере без контейнеризации. Единая база данных PostgreSQL используется для всех транзакционных и аналитических нужд. Пиковая нагрузка - 15 000 RPS, P95 латентности - 110-120 мс при допустимом пределе 100 мс.

## Компоненты и их роль
| Компонент | Назначение | Критичность |
|-----------|------------|-------------|
| Рекламный сервер| Приём HTTP‑запросов, идентификация пользователя, подбор кандидатов для аукциона. | Высокая (latency‑критичный) |
| Сервер аукциона | Применение бизнес‑правил, взвешивание ставок, определение победителя. Синхронные вызовы к БД. | Наивысшая (основной механизм) |
| Сервис выдачи | Генерация HTML/JS‑разметки баннера и формирование HTTP‑ответа. | Высокая |
| Сервис статистики | Прямая запись событий (показов/кликов) в PostgreSQL. Отсутствует буферизация. | Высокая (write‑нагрузка) |
| Финансовый сервис | Списание средств, выставление счетов, балансы. | Средняя |
| Сервис аналитики | Выполнение тяжёлых аналитических SQL‑запросов напрямую в production‑БД. | Низкая (но влияет на общую БД) |
| Рекламный кабинет | Web‑интерфейс для управления кампаниями и отчётностью. | Средняя |

## Потоки данных и выявленные проблемы

### Узкие места (Bottlenecks)
1. **Сервер аукциона** - синхронные JDBC‑вызовы к PostgreSQL в горячем пути (несколько запросов на один bid request). Отсутствие кэширования данных о кампаниях и ставках.
2. **Сервис статистики** - прямая запись каждого события в БД без буферизации, создаёт высокую write‑нагрузку и конкуренцию с транзакциями.
3. **Сервис аналитики** - тяжёлые аналитические запросы на production‑инстансе, вызывают блокировки и рост latency для всех сервисов.
4. **Единая БД PostgreSQL** - единая точка отказа для всего на свете, нет реплик, смешение OLTP и OLAP нагрузок.

### Архитектурные недостатки
- Отсутствие кэширования.
- Нет асинхронных очередей.
- Нет контейнеризации / оркестрации.
- Ручной деплой.
- Отсутствие документированной архитектуры.
- Нет выделенных SRE-инженеров.
- Монолитная связность компонентов.

### Оценка влияния на время отклика
- Синхронные вызовы к БД добавляют 30-50 мс на каждый запрос.
- Конкуренция с аналитикой и записью событий увеличивает P95 до 120 мс.
- При росте на 20% (до 18 000 RPS) прогнозируется превышение 150 мс, что нарушит SLA.

### Риски для бизнеса
- Штрафы от DSP-партнёра за деградацию latency.
- Проигрыш аукционов из-за таймаутов.
- Потеря текущих клиентов из-за нестабильности.
- Репутационные потери.
